# 투네이션 자체 필터 모델 — 라벨링 가이드 & 학습 파이프라인

목표: **사용성 최우선.** 비속어가 섞인 일반 문장은 최대한 통과시키고, **명백·악의적 욕설/혐오만 차단.**
아래는 (A) 데이터 라벨링 규칙과 (B) 학습·운영 파이프라인이다. 기존 `train.py`/`export_onnx.py`/`server.py`와 연결된다.

---

# A. 라벨링 가이드

## A-0. 원칙
1. **애매하면 통과(정상)** 쪽으로. 오차단(정상 차단)이 후원 사용성을 더 해친다.
2. **표현 자체가 아니라 "악의/공격 의도"** 를 본다. 비속어 단어가 있다고 무조건 차단 아님.
3. **문맥으로 판단**한다(앞뒤 문장, 대상). 규칙이 아니라 사람이 읽고 결정.

## A-1. 라벨 체계 (권장: 3분류 + 보조필드)
라벨러는 각 메시지에 **주 라벨 1개**를 고른다. (K-HATERS와 호환 — 그쪽 L1/L2_hate는 여기 `hate`로 합쳐짐)

| 주 라벨 | 뜻 | 후원 판정 |
|---|---|---|
| `normal` | 정상(비속어 포함 일반 문장, 강조, 감탄 포함) | 통과 |
| `offensive` | **개인 대상 욕설·모욕·인신공격** | 차단 후보 |
| `hate` | **집단/정체성**(성별·지역·인종·종교·성적지향 등) 공격·비하 | 차단 후보 |

보조 필드(선택, 있으면 품질↑):
- `severity`: `mild`(약) / `strong`(강) — 강한 것만 확실히 차단하고 싶을 때 임계값 설계에 활용
- `target`: 대상(예: individual/gender/region/race/religion/politics/age/etc)
- `evasion`: 우회 표기 여부(시★발, ㅅㅂ 등) true/false

## A-2. 판정 기준 & 예시 (매우 중요)
> 핵심: **"욕설 단어의 유무"가 아니라 "누군가를 공격하는가"** 로 가른다.

| 예시 | 라벨 | 이유 |
|---|---|---|
| 오늘 방송 **존나** 웃겼다 | normal | 강조 표현, 공격 아님 |
| **개**꿀잼 / **존나** 좋다 | normal | 감탄·강조 |
| 방송 **보지 못했어요** / **보지 마세요** | normal | 동사(보다), 욕 아님 |
| **시발점**에서 만나요 | normal | 정상어 |
| 오늘도 화이팅! | normal | 정상 |
| **씨발 꺼져** / **개객기야** | offensive | 개인 공격·욕설 |
| 스트리머 **병신** 아니냐 | offensive | 인신공격 |
| **니 엄마** ~~(패드립)~~ | offensive | 인신공격/모욕 |
| (특정 집단) **~들은 다 죽어야** | hate | 집단 혐오 |
| (지역/성별/인종 비하) | hate | 정체성 공격 |
| ㅅㅂ (단독, 대상 불명확하지만 욕설) | offensive(mild) | 욕설이나 강도·대상 약 → severity로 구분 |

**경계 규칙**
- 욕설이지만 **대상이 자기 자신/상황**("아 시발 나 왜 이러지")은 강도 약 → `offensive/mild` 또는 문맥상 `normal`. 팀 기준을 하나로 통일.
- **인용/보고**("걔가 나한테 씨발이라 했어")는 공격이 아님 → 대체로 `normal`.
- **반어/장난**은 판단이 어려우면 통과(normal). 사용성 우선.

## A-3. 특수 케이스
- **우회 표기**(시★발, ㅅㅂ, tlqkf): 뜻이 명백한 욕이면 라벨은 내용 기준(offensive/hate)으로, `evasion=true` 표시. (우회 자체는 규칙 계층이 1차로 잡지만, 학습에도 포함하면 좋음)
- **동음이의**(보지/자지/시발 등): **문맥으로** 판단. 동사·정상어면 normal.
- **성적 표현**: 단순 비속어 vs 성희롱/성적 모욕을 구분. 개인 대상 성적 모욕은 offensive/hate.
- **혼합**: 여러 요소면 **더 심한 라벨** 우선(hate > offensive > normal).

## A-4. 데이터 형식 (JSONL 권장)
한 줄 = 한 샘플. `ai-service/data/labeling_template.csv` 도 함께 제공.
```json
{"text": "씨발 꺼져", "label": "offensive", "severity": "strong", "target": "individual", "evasion": false}
{"text": "오늘 방송 존나 웃겼다", "label": "normal"}
```
- 필수: `text`, `label`(normal/offensive/hate)
- 선택: `severity`, `target`, `evasion`
- 인코딩 UTF-8. 이모지·줄바꿈은 그대로 두되 개인정보는 A-5대로 처리.

## A-5. 개인정보 비식별화 (필수)
- 후원자 실명·아이디·전화·이메일·주소·결제정보 등은 **마스킹/치환** 후 라벨링.
  - 예: 이름→`<NAME>`, 숫자열(전화/카드)→`<NUM>`, 이메일→`<EMAIL>`.
- 원문-마스킹 매핑은 라벨링 데이터에 남기지 않는다. 접근 권한 최소화, 사내에서만 처리.

## A-6. 품질 관리
- **가이드라인 문서(이 파일) 버전 고정** 후 라벨링 시작. 바뀌면 버전 올림.
- **골드셋(정답셋) 100~200건**을 먼저 팀이 합의해 만들고, 라벨러 교육·검수 기준으로 사용.
- **2명 이상 교차 라벨** → 불일치는 3번째(리드)가 결정. **일치도(카파)** 낮으면 기준 재정비.
- 정기적으로 **오라벨 샘플 검수**.

## A-7. 수량 목표(현실적 단계)
| 단계 | 규모 | 방법 |
|---|---|---|
| PoC | 1,000~3,000건 | 공개 데이터(K-HATERS) 위에 소량 투네이션 데이터로 미세조정 |
| 베타 | 5,000~20,000건 | 실제 후원 메시지 라벨링 확대 |
| 운영 | 지속 축적 | 신고/오탐을 계속 라벨링해 재학습(액티브러닝) |
- 클래스 균형 주의: `normal`이 압도적으로 많으므로 offensive/hate를 **의도적으로 더 수집**하거나 가중치·샘플링으로 보정.

# B. 학습 파이프라인

## B-0. 전체 흐름
```
수집 → 비식별화 → 라벨링(교차·검수) → 분할(train/val/test)
   → [1단계] 공개데이터(K-HATERS) 부트스트랩 학습
   → [2단계] 투네이션 데이터로 미세조정  (train.py)
   → 평가(사용성 지표) → 임계값 튜닝
   → ONNX 변환(export_onnx.py) → 서버 배포(server.py)
   → 운영 모니터링 → 신고/오탐 재라벨 → 재학습(루프)
```

## B-1. 2단계 학습 (권장)
- **1단계(부트스트랩)**: `beomi/KcELECTRA-base`(MIT)를 **K-HATERS(CC-BY 4.0)** 로 학습 → 한국어 혐오/욕설 일반 감각 확보.
- **2단계(도메인 적응)**: 그 위에 **투네이션 라벨 데이터**로 추가 미세조정 → 후원 말투·신조어에 최적화.
- 라벨 통합: K-HATERS `L1_hate`,`L2_hate` → `hate` / `offensive`→`offensive` / `normal`→`normal` (3분류로 맞춤).
- 자체 데이터로 학습한 결과물은 **투네이션 소유** → 상업 사용 자유(단, K-HATERS 부트스트랩 사용 시 출처표시 유지).

## B-2. 데이터 분할
- train : validation : test = **8 : 1 : 1** (무작위, 중복 제거, 시점 누수 방지).
- **test는 절대 학습에 쓰지 않음.** 실제 후원 메시지로 별도 **현장 평가셋**도 마련.

## B-3. 학습 (train.py 연계)
- `ai-service/train.py`의 `DATA_SOURCE`를 투네이션 데이터 경로(csv/jsonl)로 지정, 라벨 3분류로 매핑.
- 기본 하이퍼파라미터: `epochs 3, lr 2e-5, batch 16~32, max_len 128`.
- **클래스 불균형** 대응: class weight 또는 오버샘플링. (train.py에 손실 가중치 추가 가능)

## B-4. 평가 지표 (사용성 우선 설계)
"명백한 것만 차단"이 목표이므로 아래를 함께 본다:
- **정상 오차단율(False Positive Rate on `normal`)**: 낮을수록 좋음 ← **최우선 관리 지표**
- **차단 정밀도(Precision on 차단)**: 차단한 것 중 실제 악성 비율 (높게)
- 차단 재현율(Recall)은 다소 희생 가능(사람 신고로 보완).
- 카테고리별(offensive/hate) 성능, 우회(evasion) 샘플 성능 별도 확인.

## B-5. 임계값 튜닝
- 서버는 클래스 확률을 반환 → `p_bad = 1 - P(normal)`.
- **검증셋에서 곡선(정상 오차단율 vs 차단 정밀도)** 을 그려, 목표(예: 정상 오차단율 ≤ 1%)를 만족하는 **가장 낮은 임계값**을 선택.
- 서비스엔 이 값을 기본으로, 운영 중 조정. (프론트 "AI 필터(베타)" 슬라이더로 실시간 실험)

## B-6. 배포
- `export_onnx.py` 로 **ONNX int8** 변환 → `server.py`(`USE_ONNX=1`)로 서빙. **CPU로 충분**(문장당 ~10~30ms).
- 규칙(CC0 정규식, `rules.py`)로 명백 우회 1차 차단 → 나머지만 AI 호출(부하↓).
- CORS에 서비스 도메인 등록.

## B-7. 운영 모니터링 & 액티브러닝 (핵심 선순환)
- **로그 수집**: 입력·판정·확률·임계값(개인정보 비식별). 오탐/미탐 신고 버튼.
- **하드 케이스 우선 라벨링**: 모델이 애매해한(확률 0.4~0.6) 샘플, 신고된 오탐/미탐을 우선 라벨 → 적은 노력으로 큰 개선.
- **주기적 재학습**: 신조어·밈 반영 위해 월/분기 단위 재학습, 성능 회귀 없는지 test로 검증 후 배포.

## B-8. 버전 관리
- **데이터셋 버전**(라벨 가이드 버전 포함) + **모델 버전** + **임계값** 을 함께 기록.
- 롤백 가능하도록 이전 모델·임계값 보관. 배포 전 test 지표를 릴리즈 노트에 남김.
